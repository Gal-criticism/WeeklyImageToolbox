# 周边商品补搜修复记录（2026-10-18）

## 原因

原实现先采集、后下载，却在采集阶段用 `x_api_photo / socialdata_photo` 或 `goods_original` 标记决定停止商品补搜。
因此 X 附件存在、网页声称提供原图，甚至实际下载失败或原件尺寸不足，都可能让商城搜索被提前跳过。

## 修改

- 初轮保留 DOCX 来源、缓存 X 商品链接和商品详情导航；下载完成后再检查是否取得合格商品图。
- 停止补搜必须满足：商品局部证据和新闻关联成立、现有类型判断为商品、来源为商品店铺、非参考图、原图确认、实际下载/解码及哈希记录成功，原始长边至少 800、短边至少 600，并满足现有质量设置。
- X 照片独立保持优先级，不参与“商品图是否已齐”的判断。
- 未满足时只进行一次有界公开商品补搜；初轮与补搜共用 16 页、3 层预算，不重新查询 X 帖子。
- 新候选先提交到现有下载清单和检查点，再独立下载，最终进入原有分类、去重、人工复核和发布流程。
- 后台重试复用这一检查；补充链接保持仅处理指定来源，不额外扩散搜索。
- 媒体恢复可以从已登记来源恢复预算并完成被中断的补搜，不重新查询付费帖子。
- 搜索无结果、预算耗尽、采集失败分别记录中文原因；取消继续向上抛出。

## 真实补搜暴露的额外问题

- Amazon 商品详情页的推荐 ASIN 与图片可能进入采集。现仅解析当前商品主图/明确图片数据，详情页不继续导航其他商品；同 ASIN 的跟踪链接合并。
- 最大展示图不等于原图。`hiRes`、明确原图字段与最大展示变体分开；只有展示变体时保留待复核，不自动入选。
- 补搜关联增加商品种类/活动核对，避免同作品游戏封面、旧商品仅靠作品名匹配获得商品资格。
- Fantia 商品正文嵌入的站点统一推广横幅排除，不作为商品候选。

这些变化仅用于周边商品服务；新作、汉化、视频模块和 X 的优先级不变。
