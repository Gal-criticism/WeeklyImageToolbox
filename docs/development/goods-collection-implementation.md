# 周边商品来源服务

## 范围与接入

仅在 `is_goods_news` 确认为 z 栏目商品、手办、抽奖、联动或 ASMR 时使用新链路。
桌面与 CLI 的 `PipelineRunner`、重试及补抓调用同一 `GoodsSourceService`。
新作、汉化、视频下载以及 X 媒体适配器保持既有入口。

## 处理顺序

1. DOCX 保留换行和超链接目标；嵌套跟踪地址作为完整链接读取，再解析已知 DMM 落地参数。
2. 任务协调器按来源顺序采集明确链接，随后读取本新闻已有 X 响应的 URL 实体。
3. 商品解析器按站点限定主图、商品项和正文区域，取得大图、缩略图关系及商品身份。
4. 根据商品编号、作品、角色或活动判断关联。只有商城或厂牌相同不能确认关联。
5. 逐层展开相关详情，共享最多 3 层、16 页预算；记录尚未展开的链接。
6. 未取得明确关联图片时才进行商品站限定搜索；搜索结果不能触发其他 X 查询。
7. 下载、原件资产库、格式转换、去重及发布仍复用现有链路。

## 证据与筛选

`SourceRef` 增加默认空的来源链与导航深度；`ImageEvidence` 增加默认空的商品标题、卖家、
作品、厂牌、活动、图片角色、原型阶段及完整来源链。旧索引无需迁移即可读取。

`goods_*` 信号仅用于商品链路。明确关联的商品项按 GOODS 分类，ASMR 包装封面不当作游戏封面排除，
商品印刷插画不当作游戏 CG。未确认原图及资讯站参考图保持待复核。
X 照片最高优先，商品主图与设计图优先于活动集合图；既有数量、尺寸及像素确认去重规则不变。

## 失败及恢复

403/401、404/410、地区限制、超时、访问验证及服务故障分别记录。
失败来源不制造图片候选，不影响其他来源。导航和渲染复用采集响应，避免为失败页面重复请求。
补抓、下载清单、X 查询缓存和人工决定仍由原有 SQLite 与资产管理保存。

## 验证

离线测试位于 `tests/discovery/test_goods_pages.py`、`test_goods_service.py`、
`tests/pipeline/test_goods_collection.py` 及 `tests/curation/test_goods_policy.py`。
真实页面冻结和独立 265 期对照入口见 `scripts/validate_goods_collection.py`。
公开页面无法取得时必须在报告中列为未验证，不视为采集成功。
