# 审核稳定性与响应优化

## 线程与数据边界

- 重试和补充抓图共用一个后台操作入口，抓取与导出互斥，人工审核继续可用。原有同步流水线入口保留；异步重试使用真实新闻及原任务配置。
- 工作线程读取批次、检查任务内路径、计算哈希并解码图片，返回 `RetryDelta`。界面线程只合并资产增量；人工决定取合并时的最新值。
- 回调带任务、session 和操作标识；过期结果不更新当前页面。
- 审核查询与状态保存各有一个标准库工作线程。最多一个运行请求及一个可替换的后续查询；界面定时器读取已完成的 Future，工作线程不操作 QObject 或界面。
- 多选一次更新内存，状态写入按版本串行且合并等待中的旧快照，使用原子文件替换。失败显示“尚未保存”及诊断，允许重试；导出等待最新保存完成。
- 关闭窗口先停止派发、取消抓取、等待已完成资产合并及写入，再释放线程。保存失败时窗口继续保留内存状态。

## 审核列表与缓存

- 相同画面的确认缓存按新闻隔离，键包含哈希、尺寸、路径及文件版本；缓存最多 64 条新闻，每条 4096 对。仍使用哈希及像素确认，不做传递性分组。
- 未候选查询基于候选及决定快照，返回版本不匹配时丢弃。资产变化只使相关新闻的画面比较缓存失效。
- 列表按候选 ID 更新，复用原有控件、缩略图和预览。审核后移出的当前图片优先选择原位置的下一项，末尾选择前一项，保持滚动位置。
- 大列表每轮最多处理 100 项或 8 毫秒。普通审核立即更新受影响项；缓存图片文案与来源路径，避免反复对所有候选进行文件访问。
- 缩略图及预览键带资产版本，防止恢复或替换图片后继续显示旧内容。图片解码仍限两线程，QPixmap 在界面线程创建。

## 损坏记录与兼容

- 旧数据库幂等补齐表；已落盘但未登记的补抓或重试批次可恢复。SQLite 占用等待限制为 100 毫秒，避免长期冻结界面。
- 批次 JSON 或结构错误隔离整批；单条候选的归属或路径异常只跳过该条。其他有效候选及原件保留。
- 主索引、检查点和审核状态损坏明确报错，禁止以空状态覆盖。旧式决定映射与同步 `RetryAttempt` 调用兼容。
- 诊断包含阶段、候选或来源、错误码、是否可恢复、中文说明、异常类型及 HTTP 状态；Authorization、密钥和敏感查询参数脱敏。

## 离线基准

环境：Windows 11（22631）、Python 3.13.9、PySide6 6.9.2，Qt offscreen，1280×800。

固定样本含 3000 个候选、50 条新闻、2900 个初始可见备选。以无缓存、同规则参考筛选比较可见 ID 及代表版本；测试 50 次单张操作、20 次每批 50 张操作，同时运行本地慢速后台任务及 20 毫秒界面心跳。

2026-10-11 独立基准结果：

| 指标 | 实测 |
| --- | ---: |
| 单张操作即时响应 P95 | 28.9 毫秒 |
| 50 张多选即时响应 P95 | 37.2 毫秒 |
| 单张后台查询与列表同步 P95 | 156.9 毫秒 |
| 50 张后台查询与列表同步 P95 | 209.4 毫秒 |
| 界面心跳最大间隔 | 158.9 毫秒 |

即时响应指内存决定、受影响条目及下一项预览的更新；后台同步另列，不能视为已经达到 100/200 毫秒目标。操作可继续进行，不必等待后台同步。上述结果是本机离线样本的测量，不代表所有设备或实际网络任务。

基准同时核对新闻过滤、来源与原图入口、原有和新增图片导出；线程、取消、旧任务、部分恢复、过期结果、保存失败及损坏记录由独立回归覆盖。所有验证使用 mock 或本地图片，不调用付费 API、LLM 或视频下载。

2026-10-11 全项目回归：688 项通过、3 项跳过，耗时 74.21 秒。离线 X 下载夹具使用固定公网 DNS 解析，避免测试依赖系统代理的地址映射；正式请求的公开 URL 校验未放宽。测试生成的临时输出与缓存运行结束后清理，正式测试代码保留。

运行示例（仓库根目录，Windows PowerShell）：

```powershell
$env:QT_QPA_PLATFORM = 'offscreen'
python -m pytest tests/desktop/test_review_stability_benchmark.py -q -s
```

筛选标准、X 优先级、长边 800／短边 600 的备选门槛、视频流程及完整输出目录结构保持现有规则。
